# 2026-10-22：层次化评分口径修正与隐藏用例代理集

本快照补充 [`score_20261021`](../score_20261021/README.md)，公开用例的交付结果不变（仍为该快照的 `public/`）。本轮有三项改动：

1. **层次化设计的双口径守卫**：修正异步 FIFO 的结果（`extra/`）；
2. **保层次重综合**；
3. **时序隐藏用例代理集**的零 token 实测（`proxy/`）。

## 1. 课程脚本如何读层次化设计

课程 `run_demo.sh` 不展平，面积取最后一条 `Chip area for module`，`ltp` 取最后一条 `(length=N)`。实测 Yosys 0.52 的 `stat`/`ltp` **按模块名排序**输出；只含子模块实例的模块不打印面积行。同一设计因此有三种读数：

| 设计 | 课程字面读数（面积 / ltp） | 层次总面积（`Chip area for top module`） | 展平读数 |
|---|---|---:|---|
| case1 barrel_shifter | 1.862 / 1（子模块 `mux2X1`） | 44.688 | 39.4 / 4 |
| asyn_fifo | 54.264 / 36（顶层，不含 RAM） | 67.032 | 72.618 / 39 |

旧快照中 asyn_fifo 的 “-7.0%” 是展平网表：展平读数 72.618/39 → 67.564/37，但字面读数为 54.264/36 → 67.564/37，层次总面积 67.032 → 67.564，**按课程脚本是退化**。

## 2. 改动

- **守卫**（默认开启，`--flat-metric-only` 关闭）：含子模块的设计中，候选除展平口径更优外，还要按课程原版命令（不展平）重新综合，最后模块面积、`ltp`、层次总面积均不得恶化，否则判为 `course-worse`，并把原因反馈给 LLM。
- **保层次重综合**：不展平，各模块保持原名就地优化；带参数的子模块（以及参数化顶层下的全部子模块）作为黑盒原样保留。模块名不变，比较才是同口径；不靠增删或改名模块来改变被报告的模块。
- **提示词**：由“内联子模块”改为“保留层次、在模块内优化”。
- **参数守卫修复**：原先任何反引号都会被拒绝，导致带 `` `timescale `` 的 FIFO 连一个重综合候选都没有。现在只拒绝宏与条件编译。带 `#()` 参数头时，体内 `parameter`（如 `ADDR_WIDTH = $clog2(DEPTH)`）按局部参数处理。
- **验证去重**：面积、ltp、单元构成都相同的重综合/算术候选只验证一个（大设计每次验证需 3～4 分钟）。

## 3. asyn_fifo 重跑（`extra/asyn_fifo`）

`--budget normal`，`deepseek-v4.1-flash`：8 次 LLM 调用，37,585 token，110 s，**无正收益，输出原设计**。展平重综合候选（67.564/37）与 LLM 的展平改写（字面 61.446）都被守卫拒绝。保层次重综合的顶层最好为 54.796（> 54.264），其余 LLM 输出与原设计综合结果相同。barrel 的保层次候选与原设计相同（39.4/4）；展平候选（37.8/4）会使字面读数从 1.862 变成 37.8，同样被拒绝。

`extra/` 中其余 3 个单模块用例两种口径相同，结果沿用旧快照。

## 4. 隐藏用例代理集（`proxy/`）

隐藏用例全部是时序电路，其中 hidden3 有 21 个端口，与课程仓库 `case/bench/mac8` 的时序版本端口一致。我们把 5 个时序 mac8 变体（v4–v8，附课程 `stim_mac8.v`）放入 `cases/proxy/`，先用 `--offline --budget quick`（0 token）实测；对零 token 无收益的 v5/v6，再用 DeepSeek（`deepseek-v4.1-flash`，`--budget quick --max-calls 3`）重跑。快照取各用例的已验证结果：

| 用例 | 基线 面积 / ltp | 输出 面积 / ltp | Δ面积 | token | 耗时(s) | 档位 | 来源 |
|---|---|---|---:|---:|---:|---|---|
| mac8_v4_seq_shared | 3974.3 / 142 | 3131.6 / 114 | **-21.2%** | 0 | 1190 | 宽松 | 重综合 |
| mac8_v5_seq_pipe2 | 3869.5 / 161 | 1208.7 / 106 | **-68.8%** | 7353 | 758 | 严格 | LLM（datapath） |
| mac8_v6_4parallel | 3741.0 / 171 | 3675.1 / 106 | **-1.8%** | 6924 | 681 | 严格 | LLM（storage） |
| v7_seq_pipe4 | 3787.3 / 203 | 3540.7 / 190 | **-6.5%** | 0 | 884 | 宽松 | 重综合 |
| v8_seq_pipe8 | 3620.3 / 303 | 3429.5 / 212 | **-5.3%** | 0 | 711 | 严格 | 重综合 |

- **5/5 获得经验证的正收益，5/5 通过课程原版检查器**（`equiv_agent.py` + `stim_mac8.v`，见 [`proxy_course_check.md`](proxy_course_check.md)）。两种面积口径相同（单模块）。
- v5/v6 只用零 token 时，ABC 候选面积更小但 `ltp` 更深（例如 v5 为 3604.8/164，基线 3869.5/161），不满足约束。原 v5 在 `case` 的 4 个分支里共写了 10 个乘法（末分支为 `y` 重复计算一对）。DeepSeek 的 datapath 策略先按 `i` 选择操作数，再共用 2 个乘法器与一个累加器，得到 -68.8%；这类运算符共享是 ABC 做不到的。
- 宽松档是我们额外的“复位前先打拍”激励中，`done` 在复位前为 X 的差异；官方激励下逐事件严格一致。
- 耗时主要是验证：乘法器设计每个候选的仿真加有界检查约 3～4 分钟。v4 运行时尚未加入验证去重（9 个候选分两批验证，1190 s）。去重后，v5 的 DeepSeek 运行中有 2 个重复候选被跳过。
