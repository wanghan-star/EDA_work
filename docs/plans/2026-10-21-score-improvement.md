# 面向课程评分的优化实施方案

**Goal:** 在官方等价性与延时约束下增加正收益用例，并降低重复搜索成本。

**Architecture:** 保留现有 LLM、ABC、仿真与形式验证闭环；增加源代码级确定性算术候选，所有候选共用同一验收链。修正证据等级、参数化网表与独立复核的边界行为，提供可复现实测而非预测分数。

**Tech Stack:** Python 标准库、Yosys 0.52、Icarus Verilog 12、Nangate45、OpenAI 兼容 API。

## 依据与取舍

- 用户指定课程目录的 PDF 与仓库副本 SHA256 一致。
- 评分：流程 30、公开组合 15、公开时序 15、隐藏时序 30、报告 10。
- 目前公开用例 4/8 有收益；不能仅靠扩大 LLM 搜索预算提高分数。
- 选择增量强化通用候选与验收；暂不更换编排框架，不针对官方激励硬编码行为。

## 实施及验收

1. 增加零 token 算术优化候选生成器，优先测试进位输入的加法融合。
   通过小位宽穷举、参数覆盖、真实 Yosys 综合和官方时序激励验证。
2. 将确定性候选接入状态图，提供消融开关；尊重配置并发与调用上限。
3. 修正 unknown 形式证据放行，记录真实接受策略；参数化重综合不得仅恢复参数名却固化位宽。
4. 加固课程复核：缺失用例/激励、工具失败必须返回失败，保存机器可读复核证据。
5. 使用全量公开用例运行新路径，保留旧结果作为历史；统计各轮真实成本，写独立结果快照和报告补充。
6. 跑单元回归、EDA 验证链自检、原版检查器，更新 README/报告及复现命令。
